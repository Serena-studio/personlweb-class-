从零理解 Flexbox 与 Grid

2026 年 9 月 15 日 约 9 分钟 前端

很长一段时间里，我对布局的理解停留在「能用就行」——Flex 不行就换 Grid， 都不行就加个 margin 硬凑。直到认真梳理了一遍才发现， 两者的分工其实非常清晰，根本不是互相替代的关系。

一句话区分

最核心的区别在于维度的数量：

  • Flexbox 是一维布局：一次只处理一行或一列
  • Grid 是二维布局：同时处理行和列

所以判断标准很简单：如果你需要同时控制「横向」和「纵向」的对齐，用 Grid； 如果只是沿着一个方向排列一堆东西，用 Flexbox。

Flexbox：沿着一条线排列

Flex 的世界里有两根轴，这个概念必须先搞清楚：

  • 主轴：由 flex-direction 决定，默认水平向右
  • 交叉轴：与主轴垂直，默认垂直向下

最常用的几个属性：

.container {
  display: flex;
  justify-content: space-between; /* 主轴上的对齐 */
  align-items: center;            /* 交叉轴上的对齐 */
  gap: 16px;                      /* 子项之间的间距 */
}

justify-content 管主轴，align-items 管交叉轴。 这两个名字我记了很久才不混淆，后来发现一个笨办法挺管用： 「justify」有「调整使对齐」的意思，而主轴是你主要关心的那根轴。

flex 简写到底是什么意思

flex: 1 是最常见的写法，它其实是三个属性的简写： 

flex: <flex-grow> <flex-shrink> <flex-basis>;

/* flex: 1 等价于 */
flex-grow: 1;    /* 有剩余空间时，按比例放大 */
flex-shrink: 1;  /* 空间不够时，按比例缩小 */
flex-basis: 0%;  /* 分配前的初始尺寸 */

注意 flex-basis 是 0% 而不是 auto，这点很关键。 它意味着「忽略内容本身的宽度，完全按比例分配」， 所以几个 flex: 1 的元素才会等宽。

Grid：先画格子再放东西

Grid 的思路完全不同：你先定义好一个网格结构， 再决定每个元素放在哪个格子里。 

.layout {
  display: grid;
  grid-template-columns: 280px 1fr; /* 两列：固定 + 自适应 */
  gap: 48px;
}

这里有个非常好用的单位 fr（fraction，份数）。 1fr 表示「分掉剩余空间的一份」， 比写 calc(100% - 280px) 清爽太多了。

常用的三种写法

/* 1. 固定列数，均分 */
grid-template-columns: repeat(3, 1fr);

/* 2. 自适应列数：每列最小 240px，放不下就换行 */
grid-template-columns: repeat(auto-fill, minmax(240px, 1fr));

/* 3. 命名区域，语义最清晰 */
grid-template-areas:
  "header header"
  "sidebar main"
  "footer footer";

第二种写法是我个人最喜欢的——一个卡片列表不需要任何媒体查询就能自适应， 从手机到宽屏都合适。

到底该用哪个

整理成一张表，需要的时候对照着看：

场景推荐原因
导航栏、按钮组Flexbox沿一个方向排列
页面整体骨架Grid需要同时控制行列
卡片列表Grid自动换行 + 对齐
垂直居中都可以Flex 更短，Grid 用 place-items
表单标签 + 输入框Grid需要多列对齐
一行内「左边标题右边日期」Flexbox典型的一维分布

不用纠结「必须用某一个」。真实项目里往往是 Grid 搭外层骨架、 Flex 处理内部细节，两者嵌套使用才是常态。

几个容易踩的坑

1. Flex 子项的 min-width 问题

Flex 子项默认 min-width: auto， 当内容很长（比如一段不换行的英文或代码）时，它会把容器撑破。 解决办法是显式声明： 

.item {
  min-width: 0; /* 允许子项被压缩 */
}

2. gap 不是 margin

gap 只在子项之间产生间距，不会作用于容器边缘。 这比给每个子项加 margin 再处理首尾溢出要干净得多。 唯一要注意的是老浏览器支持——不过 2026 年了，这个基本不用担心。

3. Grid 里的 1fr 不等于 auto

1fr 的最小尺寸是 auto， 意味着内容过宽时它也会被撑开。如果希望严格按比例，要写成 minmax(0, 1fr)。

小结

  • 一维用 Flex，二维用 Grid，这是最根本的判断依据
  • flex: 1 = grow 1 / shrink 1 / basis 0%
  • fr 单位让 Grid 的弹性布局变得非常直观
  • 两者嵌套使用比二选一更贴近实际

写这篇的时候我把自己过去写乱的代码翻出来看了一遍， 发现大部分「玄学间距」都能用上面的规则解释清楚。挺有收获的。
