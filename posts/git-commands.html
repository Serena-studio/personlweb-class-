Git 常用命令清单

2026 年 9 月 12 日 约 6 分钟 工具

Git 的命令有上百个，但日常开发里真正高频使用的其实不超过二十个。 把最常用的整理成一份清单，忘了的时候翻一翻，比每次都去搜要快得多。

一、仓库初始化与连接

从零开始一个项目，或者把本地代码推到远程：

# 在当前目录初始化仓库（默认分支名设为 main）
git init -b main

# 关联远程仓库
git remote add origin https://github.com/user/repo.git

# 查看已关联的远程地址
git remote -v

# 首次推送并建立上游追踪
git push -u origin main

# 之后再次推送就可以简写
git push

-u 参数只需要用一次。它会把本地的 main 和远程的 main 绑定起来，之后 git push、 git pull 都不用再指定分支。

二、日常提交三连

# 查看当前改动状态
git status

# 把改动加入暂存区
git add .                 # 全部
git add index.html        # 指定文件

# 提交
git commit -m "feat: 新增文章列表页"

提交信息建议带个前缀，一眼能看出这次改了什么类型。 常见的约定有：feat（新功能）、fix（修 bug）、 docs（文档）、style（格式）、 refactor（重构）、chore（杂项）。

三、查看历史

# 简洁的单行历史
git log --oneline

# 带分支和标签的图形化历史
git log --oneline --decorate --graph

# 查看某个文件的修改历史
git log -- index.html

# 看看某次提交具体改了什么
git show <commit-id>

我最常用的是第二个，能把分支的分叉和合并看得很清楚。 提交 ID 不需要写全，前 7 位就够了。

四、撤销与回退

这一块是我最常出错、也最需要记清楚的地方。

# 撤销工作区的修改（还没 add）
git checkout -- index.html
# 或者用更直观的新写法
git restore index.html

# 把文件从暂存区撤回来（已经 add 了，但还没 commit）
git restore --staged index.html

# 撤销上一次提交，但保留改动内容
git reset --soft HEAD~1

# 撤销上一次提交，并且丢弃改动（慎用！）
git reset --hard HEAD~1

--hard 会直接丢弃改动且很难找回，用之前先确认 git status 是干净的。

简单记法：--soft 只动提交记录， --mixed（默认）连暂存区一起退， --hard 连工作区文件一起改。越往下越危险。

五、分支操作

# 新建并切换分支
git switch -c feature/comment

# 切换分支
git switch main

# 查看所有分支
git branch -a

# 合并分支到当前分支
git merge feature/comment

# 删除已经合并的分支
git branch -d feature/comment

git switch 是较新的命令，比老式的 git checkout 语义清晰——checkout 一个命令干太多事了， 容易搞混。

六、同步远程

# 拉取远程最新改动并合并
git pull

# 只下载不合并，先看清楚再决定
git fetch origin

# 查看本地与远程的差距
git log origin/main..main

养成先 git pull 再 git push 的习惯， 能避免大部分「推送被拒」的情况。

七、临时保存：stash

正在改代码，突然要切分支改别的东西，改动又还没写完不想提交—— 这时候用 stash 暂存起来： 

# 把当前改动暂存
git stash

# 查看暂存列表
git stash list

# 恢复最近一次暂存并删除记录
git stash pop

# 恢复但不删除记录
git stash apply

八、忽略文件

在项目根目录建一个 .gitignore， 把不该提交的东西排除掉： 

node_modules/
dist/
.env
*.log
.DS_Store

注意：如果某个文件已经被 Git 跟踪了，之后再写进 .gitignore 是没用的，需要先执行 git rm --cached <file> 把它从跟踪列表里移除。
